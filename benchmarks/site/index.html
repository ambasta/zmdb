zmdb — Benchmarks

zmdb run inside the actual upstream benchmark suites against real competitor libraries (moltar validation, drizzle-benchmarks ORM). Numbers are indicative of the generating machine, not an official ranking. DNF = the library cannot express that case (never summed into a score).

Validation — ops/sec across runtimes

Same code under Node, Bun, and Deno (like the moltar site). zmdb-aot is transformer-produced (the real @zmdb/aot-validator transform); zmdb (runtime) is the shipped descriptor validator. Higher = faster.

ORM — throughput & latency (full 13-route k6 vs Drizzle / Kysely, real PostgreSQL)

Honest read: zmdb leads throughput and median (p50) latency but has the worst p95 tail — a real trade-off, not a "fastest ORM" claim.
